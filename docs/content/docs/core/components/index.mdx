Components are grouped by role, not by implementation. The guides below cover usage,
variants and accessibility; the [API reference](/docs/api) carries the exhaustive props for
**every** public component, generated from the package declarations.

## Choosing a stylesheet

Historic components require `main.css`. The SDS families work with either entry; `main.css` is
the safe default while both generations are on the page. See
[CSS entry points](/docs/core/styling/css).

## Choosing between generations

| Need | Prefer |
| --- | --- |
| Page structure, sections, grids | SDS layout |
| Content card for a service, an article or a document | `SDSCard`, `SDSArticleCard`, `SDSDocument` |
| Form control | Historic `Input`, `Select`, `Checkbox`, `Upload` |
| Feedback message | Historic `Alert`, `Notice`, `Badge` |
| Data table | Historic `Table` |
