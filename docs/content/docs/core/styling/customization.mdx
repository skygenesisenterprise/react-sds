Components expose customization hooks instead of internal class names.

## Supported hooks

| Hook | Applies to | Note |
| --- | --- | --- |
| `className` | All components | Appended to the root class list |
| `style` | All components | Inline style on the root |
| `classes` | Historic components | Per-slot overrides (`root`, `title`, `description`, …) |
| `id` | Most components | Forwarded to the root element |
| Slot props | SDS families | `title`, `subtitle`, `actions`, `footer`, `media`, `tag`, `children` |

<Demo label="className + style">
  <Button className="my-button" style={{ letterSpacing: "0.02em" }}>
    Customized
  </Button>
  <SDSCard
    title="Custom card"
    description="Styled through tokens"
    variant="flat"
    style={{ borderStyle: "dashed" }}
  />
</Demo>

```tsx
<Button className="checkout-submit">Pay</Button>

<SDSCard
  title="Quarterly report"
  description="Published today"
  style={{ borderStyle: "dashed" }}
/>
```

## Do not target internal classes

`fr-*` and `sds-*` class names describe the implementation; they are not a public API and can
change between versions. Override tokens or use the props above.

## Tailwind

Two opt-in integrations exist; neither is imported by the package stylesheet.

### Tailwind v3 preset

```js title="tailwind.config.js"
module.exports = {
  presets: [require("@skygenesisenterprise/react-sds/tailwind-preset")],
  content: ["./src/**/*.{ts,tsx}"],
};
```

The preset maps Tailwind colour names onto `var(--sge-*)`. Because the values are variables,
the `/opacity` modifier is not supported; use `color-mix()` in an arbitrary value instead.

### Tailwind v4 adapter

```css title="app.css"
@import "tailwindcss";
@import "@skygenesisenterprise/react-sds/styles/adapters/tailwind-v4.css";
```

This exposes the conventional `--background`, `--primary`, … aliases used by shadcn-style
components. The canonical names remain `--sge-*`; the aliases are a compatibility layer, never
the identity.

<Callout type="info">
  The documentation portal itself uses this approach: it imports `main.css` and maps its few
  chrome variables onto the SDS tokens, with no palette of its own.
</Callout>
